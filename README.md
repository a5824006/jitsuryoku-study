# 実力試験ノート

2022～2025年度の過去問のうち、指定された9科目を分析した。
今年はその9科目から4科目を選ぶというユーザー提示の条件に合わせ、科目選択と学習、試験対策サイトの設計に使う資料をまとめた。
32件のPDF、44ページから199設問を69テーマに分類した。

- [過去問の傾向分析](reports/analysis.md)
- [科目別の全設問分析](reports/subjects/)
- [検証記録](reports/verification.md)

- [基礎教材と演習の検証記録](reports/learning-verification.md)

分析レポートをもとに、Vite・React・TypeScriptで静的サイトを実装した。
4科目の選択、科目別の年度表、69テーマの基礎教材、199設問の演習と解説、復習記録、記録のJSON書き出しと読み込みに対応する。
学習記録は各ブラウザーのlocalStorageに保存される。
設問一覧は分析時の要約を掲載し、演習画面では問題の条件を教材用に再記述する。
全199設問に解説と答案例を付け、検証済み141件、条件付き58件を区別する。
条件付き解説では、量子化規約や座標系、定義域など、補った条件を明記する。
最終結果の自動確認は21設問。論述、図示、複数の妥当な解がある問題は確認項目による自己評価にする。
公式の解答や採点基準として提示するものではない。
保存先は [a5824006/jitsuryoku-study](https://github.com/a5824006/jitsuryoku-study)。
GitHub Pagesの公開実行は後続作業とする。

## 2つの学習の入口

「基礎を思い出す」では要点、公式、解法を追う例題、確認テスト3問、条件を変えた再テスト1問を学ぶ。
69テーマで確認テスト207問、再テスト69問を用意した。
任意の基礎診断は科目の各テーマから1問ずつ出し、未診断と再確認する基礎を区別する。
過去の回答は記録を保持し、再訪時には答えを隠して練習できる。

「得点対策」では出題年度数と分母、問題の型、年度差分、答案の要求条件を確認する。
単問演習と年度別の練習セットで時間を測り、終了後に解説と確認項目を使って振り返る。
制限時間は利用者が任意に指定する。今年の試験時間や配点を推測して設定しない。
選択した科目ごとに、基礎診断の誤答、復習が必要な問題、未着手の問題の順で次の学習を提案する。

座標変換、CRCのXOR除算、ダイクストラ法には手順と条件を操作できる教材を用意した。
この条件変更演習は原本の設問数に含めない。

## 学習記録の互換性

新しい記録は `jitsuryoku-note:v2` に保存する。
旧版の `jitsuryoku-note:v1` がある場合は選択、復習状況、お気に入り、メモを引き継ぎ、元のデータを保持する。
バージョン1と2のバックアップを読み込める。
書き出し画面にはJSONファイルの保存リンクと、内容を選択してコピーする操作を用意した。
不正なファイルや保存容量の問題は画面に通知し、読み込みに失敗した記録を上書きしない。

## サイトの起動

Node.js 24以上で実行する。

```powershell
npm ci
npm run dev
```

ターミナルに表示されたローカルURLを開く。
起動時に分析データからサイト用JSONを生成する。
原本PDFを持たない環境でも、Gitで管理する分析データから起動できる。

```powershell
npm test
npm run build
npm run preview
```

本番成果物は `dist/` に生成する。
科目別データと分析レポートは必要な画面を開いたときに読み込む。
記録を別の端末へ移す場合は「書き出し」で保存し、移動先で「読み込み」を使う。
読み込むJSONのバージョン、科目、設問ID、テストID、状態、確認項目、所要時間を検査し、不正なファイルでは現在の記録を変更しない。

## GitHub Pagesの公開準備

`.github/workflows/pages.yml` にテスト・型チェック・ビルド・配信の手順を用意した。
公開段階でGitHubのSettings → PagesのSourceをGitHub Actionsに設定する。
`main` へのpushとpull requestではテストとビルドを検証する。
手動実行（workflow_dispatch）の場合だけPagesへ配信する。
リポジトリは作成済みで、Pagesへの配信はまだ実行していない。

`GITHUB_REPOSITORY` からリポジトリ配下の基準パスを設定し、画面はハッシュURLで遷移する。
独自の公開パスでは `SITE_BASE` で上書きできる。
バックアップは同じ公開元のブラウザーごとに独立するため、開発環境の記録を公開環境へ移す際にも書き出しと読み込みを使う。

## 分析データ

科目別の分類を `data/analysis/subjects/` に保存する。
`data/analysis/aggregate.json` はその分類から計算した出題頻度と全設問の索引。
`data/analysis/source_manifest.json` は対象32件のPDFの年度、ページ数、SHA-256を記録する。
集計単位と記録項目は [分析データの記録規則](data/analysis/CONTRACT.md) に従う。

教材は `data/learning/` に保存する。
起動とビルド時に全69テーマ、全199解説、276テストのID、参照先、本文、検証状態、文字数条件、図の参照を検査する。
教材データと過去問の出題集計を分離し、診断問題を過去問として重複計上しない。

独立した数値検算はPythonの標準ライブラリで再実行できる。

```powershell
python scripts/verify_math_learning.py
python scripts/verify_signals.py
```

数式表示の検査には `npm ci` で導入するKaTeXを使用する。

問題のない解答用紙も含めて44ページを目視確認した。
頻度はテーマが登場した年度数を収録年度数で割った値とする。
非表示の解答文字列と配点は採用しない。

## 再生成

Python環境には `pypdf` と `pypdfium2` が必要。
Codexのワークスペース依存ライブラリに含まれるPythonで実行できる。

```powershell
python scripts/extract_exam_sources.py "原本ZIPの絶対パス"
python scripts/build_analysis.py
```

原本ZIP、抽出したPDFとページ画像、作業用ファイルはGitに含めない。
原本を変更せずに読み取り、科目別の分類データからレポートと集計を再生成する。
